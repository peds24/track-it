Track It · v1 · iOS and Android

Keep track of what you are part-way through

Shows, movies, books, comics and manga in one list, stored entirely on your phone. No account, no server, no cover art. You open it, tap once to mark the next episode or volume finished, and close it again.

  • The title owns its line Full width to truncate into, with nothing competing with the one thing you are scanning for.
  • Kind label leads the meta line Underlined, in a fixed first position, so the eye learns one place and one mark for "what is this".
  • The count sits directly above its bar Number and measure occupy the same block, so "4 of 34" and the width depicting it are read together.
  • Standalone books have no bar Nothing to be part-way through numerically, so no progress is drawn — absence is the signal.
  • One control, one word "Done" works for an episode and a volume alike. Pressed, it inverts to solid ink rather than filling with a colour that no longer exists.

Why it is built this way

  • Text is the artwork

    No covers, no thumbnails, no placeholder tiles. A title set well at 17pt identifies a book faster than a small cover, and never shows a grey box where the artwork is missing.

  • Your library stays on your phone

    Everything lives in an on-device SQLite database. There is no account, no backend and no network call — so it works the same offline, mid-book, at 1am.

  • Two tabs, and that is all

    Currently and Backlog. There is no settings screen, no onboarding and nothing to configure — the app has one job and no preferences to hold an opinion about.

  • One list, one tap

    The app opens to Currently — only what you are in the middle of, ordered by what you advanced most recently. Marking the next episode or volume finished is a single tap.

How it works

1 · Pick a category

Show, movie, book, comic or manga. The category is chosen by you, never guessed — it decides the shape of the form, and later, which catalogue is asked.

2 · Give a title and a count

A series takes a title and a number of episodes, issues or volumes, and the app generates that many individually tracked entries. A book or a movie is just a title.

3 · Tap Done as you go

Each tap finishes the next entry and advances the row. Once something has its first entry finished it moves to Currently by itself, and falls off when it is complete.

There are no shelves in the database. Currently, Backlog and Done are queries over the same two tables — a track is in Currently if any part of it is started but not all of it is finished. Nothing has to be moved between lists, and nothing can appear in two of them at once.

You can sit half-way inside a book in a way worth recording; you cannot really do that with an episode. So watched things are binary and read things have a middle state.

Built with

PieceWhy
Expo / React NativeOne TypeScript codebase for iOS and Android, and the fastest path to a build on a real phone.
TypeScriptStrict mode throughout. The rules live in types before they live in tests.
expo-sqliteThe on-device database. Satisfies local-only storage directly, with plain migrations.
expo-routerFile-based routing for the three tabs and the add flow.
JestUnit tests for the pure domain rules, repository tests against an in-memory database.

The layering is deliberate: domain/ is pure TypeScript with no I/O — status transitions, shelf classification, progress arithmetic — and imports nothing from the database or the UI. If a rule needs a query to decide something, it is in the wrong module.

Run it

Track It is not published to any app store. It runs from source with Expo — clone it, install, and open it on your phone with Expo Go or a development build. 

# clone
git clone https://github.com/peds24/track-it.git
cd track-it

# install
npm install

# start the dev server, then scan the QR code
npm start

# or go straight to a simulator
npm run ios
npm run android

# tests and types
npm test
npm run typecheck

Not in v1

  • Next

    Export and import. The JSON backup format is written and tested — validated payloads, all-or-nothing restore — but it is not surfaced in v1 and there is no settings screen to reach it from. Until it lands, the app has no backup path at all: the library lives in one place, on one phone, and a lost or wiped device loses it. Worth knowing before you type a long backlog into it.

  • Next

    Catalogue search. Entries are typed by hand from a title and a count. Entry generation already sits behind a provider interface, so a real catalogue can be added per category later without touching the model or the tracking flow.

  • Next

    A stats page. Not a scoreboard — no ratings, no streaks — just what the columns already hold: tracks added per month by category, how long something sits in Backlog before you start it, average time to finish by category, how many tracks you completed this month and this year. No schema change needed to build it. Exportable, reusing whichever format export/import above settles on.

  • No

    Cover art or thumbnails. The v1 library is hand-typed, so most covers would be missing anyway — and a grid of grey placeholders is a worse first impression than a clean list.

  • No

    Accounts or sync. The data is small, single-user and of no value to anyone else, and conflict resolution is the expensive half of sync. Export is the intended answer to losing a device — see above for where that stands.

  • No

    Ratings or streaks. They turn a record of what you are reading into a scoreboard about it.
