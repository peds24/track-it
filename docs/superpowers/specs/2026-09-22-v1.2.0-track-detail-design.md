# v1.2.0 — Track Detail, Cover Art, Better Search & Manual Complete

**Date:** 2026-09-22
**Milestone:** ROADMAP v1.2.0 (Track Detail & Artwork), plus two additions the
user asked for alongside it: search-result disambiguation and manual
completion.
**Branches:** lands on `android` first, then ported to `web` (CLAUDE.md §6).
**Decision record:** adds **A22–A24** to `2026-08-12-track-it-design.md`.
`android`'s record ends at A17, but `web`'s already has A18–A21, so these
numbers are chosen to stay unique across both branches.

## Intent

The user's words: a per-item track screen showing "the title,
author/creator, thumbnail of cover or poster, description and stats". It
should follow the Longbox (`comic-track`) `comic/[id].tsx` layout. Search
results need to be easier to tell apart. Descriptions must stop rendering
raw HTML. Any track can be completed by hand, including an ongoing one
that has ended. All of this has to work on both android and web.

Success looks like this:

- Tapping any row opens a detail screen with a cover and clean text.
- Existing libraries get covers without re-adding anything.
- Two search hits named "Dune" can be told apart at a glance.
- An ongoing comic that ended can be moved to Done in one gesture.

## Decisions settled with the user (2026-09-22)

| Question | Answer |
| --- | --- |
| Backfill hand-typed tracks (no catalogue id)? | **No.** Backfill matched tracks only. Hand-typed ones show a placeholder and nothing is guessed. |
| Completing an ongoing series | Drop the app's auto-appended placeholder unit and mark every unit the user actually reached as done, so it reads "12 of 12", not "13 of 13". |
| Detail screen actions | All four: Advance/Resume/Start, Complete, Pause/Backlog + Delete, Edit position. |
| Thumbnails in search results | Yes. |

## A22 — Tracks store display metadata; a detail screen shows it

This reverses the no-cover-art stance in `design-language.html` ("Text is
the artwork"). The user had already made that call on 2026-09-01, and only
the landing page reflected it until now.

### Schema (migration 7)

The same five nullable columns go on both `series` and `entry`. Four hold
display data; the fifth records whether the backfill has run for that row:

```sql
cover_url TEXT, creator TEXT, description TEXT, release_year TEXT,
metadata_checked_at TEXT
```

- These are display-only. D3 still holds, because nothing here ever drives
  progress or shelf.
- A series child's own columns stay unused. Its series row holds them, the
  same rule `external_source` and `paused` already follow.
- `metadata_checked_at` exists so the backfill runs once per row. Without
  it, a row whose catalogue really has no cover would be re-fetched on
  every launch. It is stamped even when the lookup found nothing. It is
  **not** stamped when the lookup failed (network down, missing API key),
  so that row is retried next launch.
- `backup.ts` exports and imports all five columns. Older backups that lack
  them still import, with the columns set to NULL.

### Provider contract

New shared type, in `src/providers/types.ts`:

```ts
type TrackMetadata = {
  coverUrl: string | null; creator: string | null;
  description: string | null; releaseYear: string | null;
};
```

- `MetadataProvider.details?(externalId): Promise<TrackMetadata | null>`
  never throws. It returns `null` only when the lookup itself failed, which
  means "retry later". This is the single place each provider maps its own
  API response to display metadata. Both the confirm screen and the
  backfill go through it.
- `SeriesDraft.metadata?` and `MatchPreview.metadata?` carry what `hydrate`
  and `preview` already fetch. At add time, `addTrack` writes those values
  directly, so no second network call happens.
- Where each field comes from:

  | Provider | cover | creator | description | year |
  | --- | --- | --- | --- | --- |
  | Google Books | `imageLinks.thumbnail`, forced to https, `zoom=1` | `authors.join(', ')` | `description` | `publishedDate` |
  | TMDB show | `poster_path` → `image.tmdb.org/t/p/w342` | `created_by[].name` | `overview` | `first_air_date` |
  | TMDB movie | same | director, from `append_to_response=credits` | `overview` | `release_date` |
  | Metron | the matched issue's `image` | the issue's Writer credit(s) | the series `desc` | the series `year_began` |
  | AniList | `coverImage.large` | staff whose role includes "Story" (or else the first staff member) | `description` | `startDate.year` |

### Cleaning (`src/domain/formatters.ts`, pure)

- `cleanDescription(raw)` turns `<br>` and `</p>` into line breaks, strips
  every other tag, decodes named and numeric entities (`&amp;` `&quot;`
  `&#39;` `&nbsp;` `&mdash;` …), collapses whitespace, and returns `null`
  for an empty result. It is applied at the provider boundary, so stored
  text is already clean. It is applied again at render, as a defence for
  confirm-screen blurbs and any row written by an older build. AniList's
  local `stripHtml` is replaced by this function.
- `formatTimeline(...)` produces the stats lines (see the screen section).

### First-launch backfill (`src/data/backfillMetadata.ts`)

- `DatabaseProvider` fires it after migration, with no `await` and without
  blocking render.
- It selects the series rows, plus the standalone entry rows, where
  `external_id IS NOT NULL AND metadata_checked_at IS NULL`.
- Each row goes to the provider named by `external_source` (`google-books`,
  `tmdb`, `metron`, `anilist`). It calls `details()` sequentially, one row
  at a time, which keeps within Metron's and TMDB's rate limits. It writes
  the result and stamps the row. Unknown sources are stamped and skipped.
- Screens pick up the new data on their next focus reload. No live
  refresh is needed.

### Detail screen (`app/track/[kind]/[id].tsx`)

Pushed from the root stack with a header back button and the track's title
as the header title. The layout mirrors Longbox:

1. Cover: 160×240, centered, rounded, outlined. With no cover, a
   placeholder tile shows the category icon and the title's initials.
2. Title (headlineSmall), then the creator ("By …" for books, comics and
   manga; "Created by …" for shows; "Directed by …" for movies), then a
   meta line: `KIND · year · Ongoing`.
3. Progress: "12 of 34 volumes" plus a bar. A show with season data shows
   "S3 Ep 15 of 24". This reuses the row's own label and segment helpers.
4. Stats, as label/value pairs: Added (date + "3 weeks ago"), Started,
   Finished, and "Reading for 12 days" or "Finished in 4 days". Every value
   is derived from existing timestamps (D3).
5. Description: full text, collapsible after 6 lines.
6. Actions:
   - Primary: whatever the row's button says (Done/Start/Resume/Watched).
   - Secondary: Edit position (only where `canEditPosition`), Complete
     (anything not already Done), Pause/Move to backlog (anything not in
     Backlog, or Resume if paused).
   - Destructive: Delete, with a confirm.

Rows open the screen by tapping the text area. Long-press on the text area
still renames (A15). The advance button and the swipe gestures are
unchanged.

## A23 — Manual complete: the right-hand swipe becomes two-step

The left-swipe (right-side) action now mirrors the existing right-swipe
Pause → Delete:

- A short swipe does **Edit**, as today.
- A deep swipe does **Complete**, and the colour moves from
  primaryContainer to tertiary.
- A track with nothing to edit (standalone, ongoing, or backlog-unstarted)
  gets Complete as its single step. This matches how Backlog's right swipe
  is Delete-only.
- Complete is unavailable on Done.

Completion always asks for confirmation first ("Mark *X* complete?"). It
touches every unit, so one quick swipe should not be enough to trigger it.

Domain function `completeUnits(children, ongoing, now)` (pure, in
`advance.ts`):

- Every unit not yet done becomes done, with `startedAt ?? now` and
  `finishedAt = now`. Existing timestamps are never rewritten.
- For an ongoing series, the trailing unit is **removed** instead of
  completed when all of these hold:
  - it is not done;
  - its ordinal is greater than 1;
  - its `createdAt` equals its predecessor's `finishedAt`.

  That exact match is the fingerprint `appendNextOngoingEntry` leaves: the
  row was created at the instant its predecessor finished, so the user
  never reached it.
- It returns `{ updated, removedIds }`.

Data function `completeTrack(db, track, now)` runs in one transaction. It
writes the updated units, deletes the removed ones, and sets
`series.ongoing = 0, paused = 0` (or `entry.paused = 0`). Clearing
`ongoing` is what lets the derived shelf reach Done. A6 and D3 are
otherwise untouched.

## A24 — Search shows who and when; back returns to the search

- `SearchResult` gains optional `subtitle` fields: `creator?`, `year?`,
  `thumbnailUrl?`. They are filled only from data the search call already
  returns, with no per-hit follow-up fetch:
  - Google Books: authors, year, thumbnail.
  - AniList: staff, year and cover, added to the same GraphQL query.
  - TMDB: year and poster. The search API has no credits, so TMDB shows no
    creator.
  - Metron: cover date and image.
- Result rows become a 40×60 thumbnail, then the title (2 lines), then
  `creator · year` underneath. The list scrolls and is no longer capped at
  8 in a non-scrolling View.
- The confirm screen gains the cover (the same component as the detail
  screen), the creator line, and a cleaned blurb.
- "Nope, search again" is removed. The header/hardware/gesture back button
  on the confirm screen returns to the search screen with the **typed
  query and its results intact**. The query is now its own state, and
  picking a result no longer overwrites it. Back from the search screen
  still unwinds to the comic step and then the category picker, as it does
  today.

## Out of scope

- Undo toasts and celebrations (v1.1.0).
- The stats page (v1.3.0).
- Re-matching a hand-typed track to a catalogue entry.
- Covers on list rows.
- `expo-image`. RN's built-in `Image` needs no new native build and works
  on web.
