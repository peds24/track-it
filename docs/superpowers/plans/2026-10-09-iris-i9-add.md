# Iris I9 — Add Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** You can add a track on iOS the way Android does: pick a category (and, for a comic, whether it's a single issue or a collection), then type or scan to search the catalogue, pick a match, confirm it, and save it to Backlog or start it now. If there's no match, you can still add it by hand.

**Architecture:**
- **TS decision rules, held by fixtures.** The Android Add screen (`app/add.tsx`, 962 lines) keeps its decision rules inline: which catalogue answers, whether the item is a series, which barcodes apply, what the buttons say, and what gets saved. They move into a pure `src/ui/addFlow.ts`, a third `src/ui` fixture module records them, and Swift ports them to `IrisCore/Presentation/AddFlow.swift`.
- **App side.** An `@MainActor @Observable AddModel` runs the flow against an injected `AddCatalogue` (the real providers, or canned ones in tests and UI tests). `Library` gains `add(_:startNow:)`.
- **Views.** The views are a sheet: category list → comic mode → `.searchable` results → a pushed confirm screen. The scanner is VisionKit's `DataScannerViewController`.

**Tech Stack:** Swift 6.4 / SwiftUI (iOS 26), VisionKit, IrisCore providers (I5), XCTest/XCUITest; jest fixture recorder.

**Spec:** `docs/superpowers/specs/2026-10-06-iris-design.md`. This plan implements:
- §6 "`add` — Sheet with `.searchable`, provider results, scan button → VisionKit";
- §8 I9 "Add — search, provider results, barcode scan, add-to-Watched → rate prompt; §5 checklist; real search on device/simulator";
- §3, fixtures first;
- §2.2, VisionKit `DataScannerViewController`.

The decision record is D2, D5, D10, A9–A11, A14, A16, A17 and A24, all cited inline in `app/add.tsx`.

## Global Constraints

- **Behaviour and copy are `app/add.tsx`'s, verbatim:**
  - Prompts: `What are you adding?`, the comic-mode explanation, and the category note.
  - Confirm buttons: `Watched` / `Start watching` / `Start reading`, plus `Add to backlog`.
  - Manual buttons: `Watched` / `Start`, plus `Add to backlog`.
  - The match-failure note: `Couldn’t load that match — it’ll be tracked as you go.`
  - The EAN-5 prompt: `5-digit issue code?` and its body, with `Search` and `Skip`.
  - `Camera access needed` / `Camera access is needed to scan a barcode.`
  - The error alert: `Could not add track`.
  - Search debounces 300 ms and shows up to 20 results.
- **Rate prompt deferred.** The add-to-Watched rate prompt is **deferred to I10**, together with every other "rate it now?" prompt (finishing from a shelf or the detail screen). The Rate screen it opens is I10's, so asking now would lead nowhere. *This is the plan's one departure from spec §8 I9's wording; it goes to the user at plan review.*
- **No live network in automated tests** (spec §10). `AddModel` tests use canned `AddCatalogue` fakes. UI tests launch with DEBUG `-IrisCatalogue demo`, which serves canned search, hydrate and preview results, and with `-IrisScan <code>`, which stands in for the camera, since the simulator has no `DataScanner`.
- **"Real search on device/simulator"** is a manual verification step (Task 6). Run the app in the simulator against the real catalogues and screenshot real results. It needs the user's keys in `apple/Iris/Config/Secrets.xcconfig`: git-ignored and created locally from the repo's `.env` values. It is never committed, and never printed in logs or messages.
- **Native idioms (spec §5):**
  - Add is a sheet (`.irisSheet`, large detent) opened from a `+` toolbar button on Currently and Backlog.
  - Category and comic-mode choices are inset-grouped `List` rows with chevrons, pushed in the sheet's `NavigationStack`.
  - Search is `.searchable` (always shown), and the results are `List` rows.
  - The confirm screen is pushed.
  - Scan is a toolbar `IrisSymbol.scan` button, which opens a full-screen `DataScanner` cover.
  - The EAN-5 prompt is an `.alert` with a `TextField`.
- **Camera access.** `NSCameraUsageDescription` is added through `project.yml` `info.properties`: "Iris uses the camera to scan a book's or comic's barcode."
- **The app target** spells `IrisCore.Category`/`IrisCore.Progress` and never imports GRDB. Kit components are used unchanged; any change also changes `components.md`.

## Review Focus

1. **Stale async results.**
   - Typing fast, or switching category mid-search, must never show results from an earlier query or category.
   - Picking a second match before the first one's hydrate returns must confirm the second.
   - Pinned by `AddModel` tests with delayed fakes (Task 3).
2. **Hydrate failure.** A series match whose `hydrate` throws falls back as TS does:
   - the search box gets `title` (`#N` included when a scan carried one);
   - the pick is cleared;
   - the note shows;
   - saving then makes a hand-typed track.

   Pinned by an `AddModel` test (Task 3).
3. **What gets saved.**
   - A comic or manga title "Saga #12" starts at 12 (A10).
   - A manga scan's stripped volume number rides along with the pick (A24).
   - A comic collection is standalone with Google Books' source (A14/A16).
   - A standalone match keeps its preview metadata.
   - A movie saved as "Watched" lands on Done.

   Pinned by `addFlow` fixtures (Task 1) and `Library.add` tests (Task 2).
4. **Barcodes.**
   - A single-issue comic asks for the EAN-5, and Skip searches without it.
   - Book, manga and collection use ISBN symbologies; show and movie offer no scan.
   - VisionKit reports UPC-A as a 13-digit EAN-13 with a leading `0`, which must reach Metron as the 12-digit UPC-A that TS's expo-camera gives.

   Pinned by fixtures (symbologies) and a Swift test (normalisation, Task 3).
5. **Leaving mid-flow.** Back from the confirm screen returns to the same search with the box unchanged (A24). Back from search returns to the categories. Dismissing the sheet discards everything and saves nothing. Pinned by UI tests (Task 6).

### Task 3: `AddModel`

**Interfaces:**

```swift
protocol AddCatalogue: Sendable {
    func search(_ query: String, key: String) async throws -> [SearchResult]
    func hydrate(_ result: SearchResult, key: String) async throws -> SeriesDraft
    func preview(_ result: SearchResult, key: String) async -> MatchPreview
    func mangaISBN(_ isbn: String) async throws -> [SearchResult]     // Google Books manga, for A11's scan
    func comicUPC(_ upc: String, ean5: String?) async throws -> [SearchResult]
}
protocol AddLibrary: Sendable { func add(_ input: AddTrackInput, startNow: Bool, now: Date) async throws -> TrackRef }
@MainActor @Observable final class AddModel {
    var category: IrisCore.Category? ; var comicMode: ComicMode?
    var query: String                      // the search box
    private(set) var results: [SearchResult]   // ≤ 20
    private(set) var picked: SearchResult?; private(set) var pickedOrdinal: Int?
    private(set) var summary: MatchPreview?    // confirm-screen data
    private(set) var checking: Bool            // hydrate/preview in flight
    private(set) var hydrateFailed: Bool
    var pendingUPC: String?                // shows the EAN-5 alert
    var failure: ShelfModel.Failure?
    private(set) var saved: TrackRef?      // the sheet closes when set
    var isSeries: Bool { get }; var barcodeKinds: [BarcodeKind]? { get }
    init(catalogue: any AddCatalogue, library: any AddLibrary, debounce: Duration = .milliseconds(300))
    func choose(_ c: IrisCore.Category); func chooseComicMode(_ m: ComicMode)
    func queryChanged()                    // debounced search; clears pick, scan ordinal, note
    func pick(_ r: SearchResult)           // starts hydrate (series) or preview (standalone)
    func unpick()                          // back from confirm: keeps query
    func scanned(_ payload: String) async  // A9/A11 routing; comic single → pendingUPC
    func submitEAN5(_ code: String?) async
    func save(startNow: Bool) async
}
```

- [ ] **Step 1: Failing tests** (`AddModelTests`), with a `FakeCatalogue` that can delay and fail per call, and a `FakeAddLibrary`:
  1. A debounced search queries once per pause.
  2. A late response for an old query is dropped (Review Focus 1).
  3. Switching category mid-search drops results.
  4. Picking B while A's hydrate is pending confirms B.
  5. A failed hydrate moves the title into `query` (with `#N` after a scan), clears the pick, and sets `hydrateFailed`.
  6. Manga scan: an ISBN gives the Google Books title `"Attack on Titan 30"`, which `stripBareTrailingNumber` turns into a search for `"Attack on Titan"` with `pickedOrdinal` 30 once picked.
  7. A comic single scan sets `pendingUPC`; then `submitEAN5(nil)` searches by UPC without a code, and `submitEAN5("12345")` with it.
  8. `save` builds the input with `addTrackInput` and calls the library with `startNow`. It sets `saved`; a failure shows `Could not add track`.
  9. `unpick()` keeps `query`.
  10. Results are capped at 20.

  Use `debounce: .zero` and controllable fakes, not sleeps.
