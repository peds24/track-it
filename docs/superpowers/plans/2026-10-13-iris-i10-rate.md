# Iris I10 — Rate, Rankings and the Rate Prompts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rate finished tracks on iOS the way Android does (A26). First you say how you felt, then you answer a short run of "which did you prefer?" against your other rated tracks in the same category. The 1–10 score comes from where the track lands. You can see the ranking per category. Every place a track finishes (a shelf advance, Complete, the detail screen, Add as Watched/Start) offers "Rank it now?". The I8 rating card and the I7 Done rows gain their Rate buttons.

**Architecture:**
- **Already there.** The ranking engine (`startRanking`, `answer`, `isPlaced`, `matchupReason`, `scoreAt`) and the data layer (`ratingProfileOf`, `listRanking`, `getRating`, `saveRating`) are already in IrisCore, held to TS by I3 fixtures and I4 scenarios.
- **The screens' words.** The text of the Rate and Rankings screens and of the prompt moves into `src/ui/rateText.ts`, the fourth `src/ui` fixture module, and is ported to `IrisCore/Presentation/RateText.swift`.
- **App side.** `Library` gains thin wrappers. An `@MainActor @Observable RateModel` runs the session: choose, answer, tie, undo, save. `RateView` is a sheet and `RankingsView` a pushed list.
- **The prompt.** One shared modifier, `.ratePrompt(...)`, asks "Finished X / Rank it against the other … you’ve rated?" after any action that finished an unrated track.

**Tech Stack:** Swift 6.4 / SwiftUI (iOS 26), IrisCore (I3–I5), XCTest/XCUITest; jest fixture recorder.

## Global Constraints

- **Behaviour and copy are `app/rate/[kind]/[id].tsx`, `app/rankings.tsx` and `src/ui/rating.ts`, verbatim:**
  - Prompts: `How was it?`, the three sentiment labels, `Which did you prefer?`, `Too tough to call`, and `Change how I felt` / `Undo last answer`.
  - `Question N · among the <plural> <group>`.
  - The existing-rating note.
  - The footnote: "You’ll compare it with other … where it lands."
  - The result screen: `#r of n <plural>`, `Done`, `See your <plural>`.
  - Rankings: the title `Rankings`, the empty copy, and the row label `Number r, title, s out of 10`.
  - The prompt: `Finished <title>` / `Rank it against the other <plural> you’ve rated?` with `Later` / `Rate it`.
  - Failure: `Could not save rating`.
  - Not found: `This track couldn’t be found — it may have been deleted.`
- **Nothing is saved until the track is placed** (A26). Backing out at any point leaves an earlier rating as it was. Rating again replaces the old rating only on placement.
- **Rankings** are one category at a time, with no "All" (A26). TS order is Movies, Shows, Books, Comics, Manga, and the default is Movies unless a category is passed.
- **Native idioms (spec §5):**
  - Rate is an `irisSheet` (large detent) holding its own `NavigationStack`.
  - The comparison step uses two `IrisComparisonCard`s (I6), side by side, stacked at AX sizes.
  - The result shows an `IrisRatingBadge` at a large size.
  - Rankings is pushed from Done's toolbar (`IrisSymbol.rankings`) and from the result's `See your <plural>`. It has a segmented `Picker` and a plain `List` of rows: rank, cover, title, "creator · year", and a badge.
  - The prompt is an `.alert`.
  - Haptics: `.selection` on each answer (the card already does this), and `.success` on placement.
- **Where the prompt fires** (`offerRatingIfFinished`'s call sites), only when the track is now Done and unrated:
  - shelf advance (row button, leading swipe);
  - shelf Complete;
  - detail primary and Complete;
  - Add with startNow.

  It fires after the action succeeds, never on failure.
- **The app target** spells `IrisCore.Category`/`IrisCore.Progress` and never imports GRDB. New models cancel via `TaskBag` (no `isolated deinit`). Kit components are used unchanged; any change also changes `components.md`.

## Review Focus

1. **The three-track walk-through (done-when).** On a library with three rated movies in the same sentiment, rating a fourth movie asks at most two questions and lands at the right rank. The score shown equals `scoreAt` for that position, and Rankings shows all four in order. Pinned by a `RateModel` test with real `startRanking`/`answer` (Task 3) and a UI test (Task 6).
2. **Backing out.**
   - Dismissing the sheet mid-session saves nothing.
   - `Change how I felt` with no answers returns to the sentiment step.
   - `Undo last answer` restores the previous question.
   - Re-rating a rated track and backing out keeps the old score.

   Pinned by `RateModel` tests (Task 3) and a UI test (Task 6).
3. **The first rating in a category,** with nothing to compare against, is placed immediately with no questions (`isPlaced(started)`). The result shows `#1 of 1`. Pinned by a test (Task 3).
4. **The prompt never nags.** It never shows after a failed action, for a track that isn't Done, or for one already rated. "Later" leaves a Rate button on the Done row and the detail card. Pinned by tests in each model (Task 4).
5. **Ties and long titles.**
   - `Too tough to call` places the track next to the opponent, as the engine says.
   - Two long titles side by side at AX5 stack instead of truncating, and the rankings rows wrap.

   Pinned by the `answer(.tie)` path in a model test and by the AX5 screenshots (Task 6).

### Task 3: `RateModel`

```swift
protocol RateLibrary: Sendable {
    func rateContext(_ ref: TrackRef) async throws -> RateContext?
    func saveRating(_ track: RatableTrack, sentiment: Sentiment, indexInBucket: Int, now: Date) async throws -> RatingSummary
}
@MainActor @Observable final class RateModel {
    enum Step: Equatable { case loading, missing, sentiment, comparing, saving, result(RatingSummary) }
    private(set) var step: Step
    private(set) var context: RateContext?
    private(set) var session: RankingSession?
    private(set) var history: [RankingSession]
    var failure: ShelfModel.Failure?
    init(ref: TrackRef, library: any RateLibrary)
    func start() async
    func choose(_ s: Sentiment) async      // startRanking; placed at once → save
    func answer(_ a: Answer) async          // pushes history; placed → save
    func undo()                             // pop history, or back to .sentiment
    var opponent: RankedTrack? { get }       // ranking row for session.bucket[session.opponent].key
    var reason: String? { get }              // matchupReason(profile, opponent item)
}
```

- [ ] **Step 1: Failing tests.** Use a fake library holding real `RankedTrack`s, and the real engine.
  - **The three-track walk-through:** an Interstellar candidate liked against 3 liked movies asks ≤ 2 questions. Answering `.candidate` every time places it at index 0, then saves with `indexInBucket` 0. The result's rank comes from the fake.
  - **The first in a category:** saved at once, `.result`, no questions.
  - **A tie:** places next to the opponent, per `answer(.tie)`.
  - **Undo:** pops one question; with no answers, `undo` returns to `.sentiment` without saving.
  - **A failed save:** shows `Could not save rating` and returns to the last question, so you can retry.
  - **A missing context:** `.missing`.
